# Standalone PowerON Bot

Окремий Telegram-бот для перегляду графіків відключень з `poweron.toe.com.ua`.

## Що вміє бот

- Покроковий пошук адреси: **населений пункт → вулиця → будинок**.
- Отримання та відправка скріншота фрагмента графіка відключень.
- Показ черги з API (лише ГПВ).
- Історія останніх 6 адрес.
- Закріплення до 6 адрес для швидкого доступу.
- Екран **⚙️ Налаштування** з керуванням автооновленням.
- Кнопки користувача для якості сервісу: **⭐ Оцінити бота** та **📝 Зворотній зв'язок**.
- Команди `/status` і `/faq` для швидкого перегляду стану та довідки користувача.
- Self-test команди для адміністратора: `/selftest_logs` (тест запису логів) і `/selftest_plot` (тест PNG-графіка в headless режимі).
- Команда `/download_logs` надсилає на пристрій адміністратора файли `admin_actions.log` і `user_entries.log`.
- Адмін-меню з командами `/stats`, `/analytics`, `/broadcast`, `/health`, `/download_logs`, `/users_export`, `/logs_tail`, `/feedback_view`, `/feedback_export`, `/ratings`, `/feature_flags`, `/shutdown`, `/restart` (лише для адміна).
- `/broadcast` працює з попереднім переглядом і підтвердженням перед масовою розсилкою.
- Адмін-меню відкривається командою `/admin` або автоматично для адміна після `/start`.
- Логування входів користувачів у абсолютний файл `logs/user_entries.log` (автостворення директорії `logs/`).
- Окремий аудит адмін-дій у абсолютний файл `logs/admin_actions.log`.
- При критичній помилці polling бот автоматично перезапускається з паузою 5 секунд.
- Збереження персональних налаштувань (історія/закріплені адреси) у `data/users.json (ключі — chat_id)`, включно з `auto_update` (enabled/interval/silent).
- Запис `data/users.json` виконується атомарно + з backup у `data/users.json.bak`.
- Кеш графіків спільний для всіх користувачів (без дублювання рендеру для однієї адреси).

## Підготовка до запуску

### 1) Встанови залежності

```bash
pip install -r requirements.txt
python -m playwright install chromium
```

### Ubuntu 22.04 (важливо для скріншотів)

Якщо на Ubuntu 22.04 не формується скріншот, встановіть системний Chromium і залежності Playwright:

```bash
sudo apt update
sudo apt install -y chromium-browser
python -m playwright install chromium
python -m playwright install-deps chromium
```

За потреби можна явно задати шлях до браузера:

```bash
export POWERON_BROWSER_PATH="/usr/bin/chromium-browser"
```

> Для Termux: бот підтримує HTTP-клієнт **httpx** або **requests**. Якщо з `httpx` є проблема у середовищі, можна використовувати `requests` (вже додано в `requirements.txt`).

### 2) Налаштуй токен бота

Підтримуються 2 способи (пріоритет має змінна оточення):

1. Через ENV:

```bash
export POWERON_BOT_TOKEN="<YOUR_TELEGRAM_BOT_TOKEN>"
```

2. Через файл у корені репозиторію:

- Скопіюй шаблон `poweron_bot_token.txt.example` у `poweron_bot_token.txt`.
- Встав токен в **один рядок** без лапок.

> `poweron_bot_token.txt` має бути локальним файлом і не має комітитись у git.

### 3) (Опційно) обмеж доступ до бота

```bash
export POWERON_ALLOWED_IDS="123456,987654"
```

або дозволити використання лише адміну:

```bash
export POWERON_ADMIN_USER_ID="123456"
```

`POWERON_ALLOWED_IDS` обмежує доступ користувачів до бота.
`POWERON_ADMIN_USER_ID` (або `poweron_admin_user_id.txt`) визначає адміністратора для адмін-команд `/admin`, `/stats`, `/health`, `/broadcast`.
Якщо не задавати `POWERON_ALLOWED_IDS` — бот доступний усім, хто має доступ до нього в Telegram.

## Нові покращення (v2)

- `/analytics` — агрегована статистика (запити/успіх/помилки/нотифікації).
- Розумні автооновлення: quiet-hours + ліміт повідомлень за годину для зменшення спаму.
- Fallback після помилки рендеру має кнопку `🔁 Спробувати ще раз`.
- `/users_export` — CSV експорт стану користувачів.
- `/users_export` підтримує режими: `all`, `active`, `auto` (також через інлайн-вибір в адмін-меню).
- `/logs_tail` — швидкий перегляд останніх рядків логів прямо в Telegram.
- `/feature_flags` — керування функціоналом без деплою (інлайн-меню з перемикачами + `/feature_flags <name> <on|off>`).
- Кнопка `🚨 Інцидент` в адмін-меню: health + швидка чистка кешу + короткий tail логів.
- Автооновлення для вибраних користувачем адрес (до 6).
- Перехід на SQLite storage (`data/users.sqlite`) для стабільнішого збереження станів.
- Кеш має policy через ENV: `POWERON_CACHE_MAX_FILES`, `POWERON_CACHE_MAX_FILE_AGE_SECONDS`, `POWERON_CACHE_LOW_DISK_FREE_MB`.

## Пріоритетний roadmap

### Phase 1 (1–2 тижні) — швидкий видимий ефект

- UX cleanup головного екрану (єдина кнопка `🏠 Додому`, чіткіші короткі підказки на старті).
- Метрики продуктивності: додати p50/p95 для API, рендеру скріншота та доставки повідомлень.
- Надійніша розсилка `/broadcast`: exponential backoff, окрема обробка `429` і timeout-помилок.
- Розширити `/health`: показ черги автооновлень, частоти retry та топу типів помилок.

### Phase 2 (2–4 тижні) — стабільність і масштабування

- Оптимізація API-пошуку: серверна пагінація/фільтрація або локальний TTL-кеш довідників.
- Перехід на SQLite-first persistence (JSON залишити як snapshot/backup), щоб зменшити I/O overhead.
- Розумний кеш графіків: adaptive TTL, negative cache для помилок рендеру, pre-warm топ-адрес.
- Удосконалення автооновлень: профілі частоти сповіщень і подієві тригери замість лише інтервалів.

### Phase 3 (4–6 тижнів) — продуктове зростання

- Режим порівняння адрес (2+ адреси): різниця черг/станів в одному повідомленні.
- Таргетовані сповіщення: «лише при зміні черги», «лише критичні зміни», «лише в обрані години».
- Поліпшений фідбек-цикл: структурований фідбек після низької оцінки та автоматичні теги причин.
- Адмін-аналітика: retention, DAU/WAU, ефективність автооновлень, тренди помилок по днях.

### KPI для контролю прогресу

- Час відповіді бота (p95) < 3с для текстових сценаріїв.
- Успішність рендеру графіка > 98%.
- Частка корисних автосповіщень (без «шуму») > 70%.
- Зниження повторних запитів на ту саму адресу мінімум на 20% (за рахунок кешу/UX).

## Логи та self-test

- Логи пишуться у:
  - `/home/ubuntu/Poweron_bot/logs/admin_actions.log`
  - `/home/ubuntu/Poweron_bot/logs/user_entries.log`
- Директорія `logs/` створюється автоматично.
- Перевірка логів: виконайте `/selftest_logs` від адмін-акаунта, потім перевірте обидва файли.
- Завантаження логів у Telegram: виконайте `/download_logs` або натисніть кнопку в адмін-панелі.
- Перевірка PNG-графіка: виконайте `/selftest_plot` від адмін-акаунта — бот надішле тестовий PNG, згенерований через matplotlib backend `Agg`.

## FAQ

- **Як швидко подивитись графік?**
  Натисніть `⚡ Перевірити графік` і пройдіть кроки: населений пункт → вулиця → будинок.

- **Що надсилає бот?**
  Скріншот графіка з сайту та значення `ГПВ` з API.

- **Скільки адрес зберігається?**
  До 6 в історії та до 6 у закріплених.

- **Як працює автооновлення?**
  У `🎛 Налаштування` відкрийте автооновлення, увімкніть інтервал і в меню `📍 Адреси для автооновлення` відмітьте потрібні адреси (можна кілька).

- **Що робить тихий режим?**
  Надсилає повідомлення тільки якщо графік змінився.

- **Як залишити відгук або оцінку?**
  На головному екрані натисніть `📝 Відгук` або `⭐ Оцінка` і оберіть значення 1..5. Оцінку можна залишити один раз.

## Поширені проблеми

- **`Set POWERON_BOT_TOKEN or create poweron_bot_token.txt`**  
  Не задано токен через ENV і відсутній файл `poweron_bot_token.txt`.

- **Playwright не запускає Chromium (особливо Ubuntu 22.04)**  
  Виконай: `python -m playwright install chromium && python -m playwright install-deps chromium`, встанови `chromium-browser` і за потреби задай `POWERON_BROWSER_PATH=/usr/bin/chromium-browser`.

- **`ModuleNotFoundError` на залежностях**  
  Перевстанови пакети: `pip install -r requirements.txt`.


## Інтерфейс

- На головному екрані reply-меню: **"⚡ Графік"**, **"📌 Адреси"**, **"🕘 Історія"**, **"🎛 Налашт."**, **"📡 Статус"**, **"❓ FAQ"**, **"⭐ Оцінка"**, **"📝 Відгук"**, **"🏠 Додому"**.
- Inline залишився лише там, де це критично: вибір адреси зі списку та динамічні дії з історією/закріпленими адресами.
- Після вибору адреси бот надсилає повідомлення **"⏳ Очікуйте..."** під час завантаження графіка.
- Доступне автооновлення графіка: **увімкнути/вимкнути**, пресети **30с / 60с / 120с**, власний інтервал (мінімум 10с) та вибір адрес для автооновлення.
- Автооновлення в тихому режимі надсилає оновлення лише коли графік змінився (без спаму).
- Діє rate-limit на часті запити користувача, щоб не перевантажувати API.
- Натискання **"💡 Графік світла (за адресою)"** завжди скидає сценарій і повертає в початок пошуку адреси.
- Команди `/status` і `/faq` доступні користувачу в будь-який момент.
- Адмін може переглянути загальну оцінку (`/ratings`) та переглянути/експортувати відгуки (`/feedback_view`, `/feedback_export`).

## Рекомендований systemd unit

```ini
[Unit]
Description=PowerON Telegram Bot
After=network.target

[Service]
Type=simple
WorkingDirectory=/home/ubuntu/Poweron_bot
Environment=PYTHONUNBUFFERED=1
ExecStart=/home/ubuntu/Poweron_bot/.venv/bin/python -m poweron_bot.main
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> Важливо: використовуйте Python з вашого venv і запуск модулем `-m poweron_bot.main`, щоб імпорти працювали стабільно.
